# Standalone Portrait Stage — beta.14

2026-11-09 · Northern Lights Labs. Implements Delivery C / Phase 3 of the [photo plan](56-NARCISSUS-PHOTO-ARCHITECTURE.md), after checking [Delivery B](58-PHOTO-COMPOSITION-AND-OUTPUT.md). Original LumenShift code; no Narcissus code, artwork, databases, API, library or TOC dependency. The optional coexistence adapter is separate.

## Phase 2 audit

The unchanged beta.13 baseline passed all **547 Lua 5.1 mock tests**. Review found a specific interruption bug: Escape could wait for a pending zoom to finish, but combat/world departure discarded its completion callback. Camera could then remain busy. Cancellation now finishes that pending exit with an interruption result, retains the original zoom record and requests no automatic return. PC01 covers it; existing output, framing, collision, ownership and lifecycle tests remain intact.

## What Phase 3 adds

Camera opens in **World Photo**, as before. The new **Portrait Stage** button explicitly creates independent UI models. It starts with the player and supports a maximum of three actors drawn from the current player, target and pet. The world continues running behind the stage; this cannot pause the game.

| Control | Delivered behavior |
|---|---|
| Actors | Add me / target / pet; select or remove each actor. Live horizontal, vertical, depth, scale, turn, tilt and roll sliders. |
| Pose | Stand, Walk, Run, Talk, Wave and Dance; Play / Pause, playback speed and a 0–10 second pose offset. Scrubbing pauses the model. This is an offset, not a claim about animation duration. |
| Appearance preview | Sheathe/hide weapons, use transmog appearance, hide helmet/cloak. Rebuilds a staged copy; never equips, undresses or transmogrifies the real character. |
| Light | Original Neutral, Softbox, Firelight and Moon rim recipes. Live direction/elevation, ambient fill, key intensity and key RGB. Relights models only. |
| Scene | World, charcoal, gray, green or blue backgrounds; stage camera distance, height and field of view; thirds guide and letterbox. Stage lens is separate from native world camera/FOV. |
| Look | Existing filters, vignette, glow, grain, edge light, comparison and undo/redo also work over the stage. These remain screen treatments. |
| Saved | Up to eight versioned scenes and eight independent model-light presets. Stores layout/pose/lighting/background and symbolic unit sources, not identities or extracted model assets. Loading a target/pet slot uses the current target/pet. |
| Capture | Existing single shot, timer/burst, Hide controls/H and Escape. Capture freezes staged actors and resumes their prior play/pause state after the result. No global animation pause. |
| Compositing pair | Two completion-gated screenshots: background without actors, then actors on green. Screen treatments are omitted from both passes, then restored. Separate normal image files, not transparent PNGs, a true silhouette/depth mask or a layered PSD. |

The native world-photo Light/Frame/Pose tools remain under World Photo. Portrait controls do not operate those world settings. Existing explicit output-quality controls remain on Capture. No new setup/reset, confirmation card or command sequence is required.

## Architecture and lifecycle

- `PortraitConfig` owns strict version-1 scene, actor and lighting schemas, allowlisted unit/pose/background values, finite control bounds and bounded save banks. Unknown fields, scripts, arbitrary unit tokens and model-ID imports are rejected. These numeric limits are LumenShift UI limits, not inferred engine maxima.
- `PortraitBackend` creates an owned native `ModelScene`, native actors and model lighting only on entry. There are six reusable actor objects: front/back for each of three slots. Failed replacement never discards the visible front buffer. The standard Blizzard actor template supplies native scale bookkeeping; no custom per-frame polling is installed.
- A deliberately separate `DressUpModel` fallback is used when scene creation/core methods are absent. It provides staged cast transforms, appearance, supported poses, pause, lighting and backgrounds. The fallback explains that timeline/speed and stage lens need ModelScene; it does not guess undocumented time units or silently retry a restricted unit through another backend.
- Loading checks accessible unit existence/identity, the optional native identity-restriction predicate, native success and readiness. A changed target invalidates that replacement. Polling is bounded to twenty 0.25-second observations and cancelled by a session generation. Existing actors survive rejection, timeout or unsupported appearance. Per-slot failure messages remain available even when another slot succeeds.
- There are no new CVar writes. The existing single native writer remains in `WriteBoundary.lua`; model mutations operate only on owned UI model objects. The stage does not use view slots, change world camera motion, access other addons' saved data or equip the player.
- Ordinary captures pause each actor locally (`SetPaused(true, false)` for ModelScene actors). The second argument explicitly avoids the native global pause default. Failure/timeout restores previous pause states while the same stage is active. Exit, combat, world leave and reset hide, pause and clear actors; stale callbacks cannot repopulate a new scene. H hides controls without hiding the artwork. Reduced Motion loads models paused; explicit Play still works.
- Schema **16** adds the portrait container while preserving setup completion, visual/quality settings, photo looks and recovery records. Invalid existing portrait data is not overwritten with defaults. Scene storage is data-only and shares the repository's bounded-copy validation. Nothing is instantiated or replayed automatically at startup/reload, even when saved actors were playing. SavedVariables durability remains subject to WoW's normal save behavior.
- Reports include backend, active/loading state, actor/failure counts and save counts. They omit scene/light names, unit GUIDs and appearance identities. All four new modules are ordinary Lua, with no new downloaded asset or runtime dependency.

## Installation and owner test

1. Exit WoW. Extract the supplied **beta.14 ZIP**, and replace only the installed **LumenShift** addon folder with its complete extracted folder. The path ends in `_forever_/Interface/AddOns/LumenShift/LumenShift.toc`; Core, UI, Media and Bindings.xml sit beside it. Keep SavedVariables. There is no new setup wizard for this update.
2. For the standalone check, disable Narcissus in AddOns (uninstalling is unnecessary). Enable LumenShift and enter the game. Open the logo/wheel and choose **Camera**. World Photo should still provide existing Look, native Light, Frame, Pose, Capture and Saved tools.
3. Click **Portrait Stage** near the top of Photo Studio. Your staged player should appear against charcoal. Under **Actors**, move/turn/scale it. Add a target, optionally a pet; select each row to adjust independently. Try replacing an unavailable target: the existing cast should remain visible and a local message should explain it.
4. Scroll Actors to Pose. Try Wave or Dance, Play/Pause, then move Pose offset while paused. Test sheathing and helmet/cloak previews. Confirm your real equipment is unchanged after leaving the stage. Race/form-specific pose support and appearance refresh need this visual check.
5. Open **Light**. Try Firelight/Softbox and drag direction, intensity and color. These should visibly affect the staged cast. Open **Scene** for backgrounds and the stage lens. Open **Look** for existing vignette/filter/glow treatments. Confirm native world-light values do not change when editing model light.
6. Under **Saved**, save a scene and a separate light; change them, then load each. A saved target means the currently selected target when loaded. **World Photo** clears staged actors and returns the world composition without leaving Camera Mode. Re-enter Portrait Stage to continue.
7. Take a normal screenshot. Confirm controls/guides are absent and models/treatments remain. Press **H** for an external capture, H again to return controls. Under Capture, scroll past timer controls to **Compositing pair**: expect two files in WoW's Screenshots folder, backdrop first and green-screen cast second. They are ordinary separate images for external editing; the world may move between frames.
8. Press **Escape**. Confirm the HUD returns, models disappear, no staged animation remains, and existing temporary native photo settings restore where still owned. Re-enter and try a timed capture. Exit during a pending load/countdown; it must not reopen later. After a normal reload, saved scenes should remain but no stage/capture should start automatically.

If a native model API rejects a feature, World Photo and other usable stage controls remain available. Export the report and include which control and race/form failed; do not reset saved settings to test this update. Native rendering may need tuning for very large creatures, particle-heavy models or particular forms. The fallback does not promise shared-scene depth sorting. A live world background cannot be frozen for compositing. Public release, native visual sign-off, further spell effects and CurseForge publication are outside this update; branch/PR #5 remain unmerged.
