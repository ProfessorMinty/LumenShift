## Controls delivered

| Frame | Hold orbit left / right | Starts native orbit only while deliberately held; release, leaving the button, hiding controls, Escape, combat, world leave and reset request Stop. | Frame | Shoulder offset, Dynamic framing, Dynamic footroom | Coalesced live CVar preview through the existing framing planner and writer. | Capture | Ray-traced shadows | Off/Fair/Good/High only when native renderer/value checks allow each option. Uses the existing independent photo-quality bank and its original, including when temporary photo quality was already active. |
| Capture | JPEG quality 1–10, Apply / Restore | Available when the accessible screenshot format is JPEG and quality/security metadata is usable. Changes compression quality, not image dimensions or world detail. Does not switch format. Exit restores the original. |
| Look | Sun Flare, Blue Hour, Edge light strength/position/width | Original additive light-leak treatment, reusing LumenShift's existing licensed original glow texture. Live cosmetic sliders and look Undo/Redo apply. This is screen artwork, not world relighting or a new shader. |

## Source and API decisions

Reviewed primary sources are pinned; a source declaration is not proof of behavior on the owner's current renderer.

- Forever 70862's [native graphics options](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_SettingsDefinitions_Shared/Graphics.lua#L998) parses `MSAAQuality` as an index/coverage pair. `AntiAliasingSupported()` supplies FXAA/CMAA/CMAA2 capability flags; `MultiSampleAntiAliasingSupported()` supplies quality/sample/coverage triples. The native UI associates `ffxAntiAliasingMode`, `MSAAQuality` and `MSAAAlphaTest`. LumenShift captures all three, including unchanged members. It does not issue the author's reference console strings.
- The same source [validates alpha-tested edges](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_SettingsDefinitions_Shared/Graphics.lua#L1151) and [ray shadows](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_SettingsDefinitions_Shared/Graphics.lua#L1292). Ray choices require secondary lighting disabled, a non-Mac client, and `IsGraphicsSettingValueSupported("shadowrt", value, false) == 0`. The [video API enum](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_APIDocumentationGenerated/VideoDocumentation.lua) declares zero as Supported. No hardware capability is inferred from an RTX label.
- These selected AA/ray UI definitions use the native Apply path without a graphics-restart flag. LumenShift issues no renderer change, console execution, `GxRestart`, Settings reset or broad graphics setter. If fresh option validation or immediate/delayed readback fails, the operation is not reported as successful. Native visual application/performance still requires testing.
- [Native FOV bounds](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_APIDocumentationGenerated/CameraDocumentation.lua#L10) remain authoritative for FOV. The [historical Forever CVar inventory](https://github.com/Ketho/BlizzardInterfaceResources/blob/d1ee569878094270c0ad8d8b00de0762158fd578/Resources/CVars.lua) supplies camera names/help and documents screenshot quality 1–10. Current accessible values, flags, API availability and effective readback are checked at runtime. Historical inventory values are not promoted into claimed native acceptance.
- Shoulder −3..3, dynamic footroom 0..1 and requested zoom 0..50 are **LumenShift control limits**, not engine maxima. Dynamic pitch is boolean. Existing FOV bounds are not reused for other settings. `CameraKeepCharacterCentered` and `CameraReduceUnexpectedMovement`, when enabled, disable the affected optional framing controls without being changed themselves.
- The reference author's [camera adapter](https://github.com/Peterodox/Narcissus/blob/0a6d5985f6604fdb39190f284def6864f3622a8b/Narcissus/API/Camera.lua) corroborates native zoom and start/stop movement APIs. The [screenshot-quality UI](https://github.com/Peterodox/Narcissus/blob/0a6d5985f6604fdb39190f284def6864f3622a8b/Narcissus/SettingsFrame.lua#L1900) uses a narrower slider. This is behavior/API research only: no source or artwork was copied, no camera slots/foreign preferences are manipulated, and no dependency was introduced.

## Architecture and failure handling

`Framing` extends the existing numeric catalog/planner/recovery path; `PhotoPreview` coalesces native slider requests. `CameraActions` isolates native zoom/orbit from CVar operations. It saves the initial observed zoom, distinguishes actual settled readback from requested distance, refuses to overwrite a later external zoom and retains failed originals. Keep current zoom deliberately releases only that distance record. Orbit has no background update loop. A one-shot native zoom animation may finish after a cancellation; LumenShift invalidates its polling and does not guess a new return distance after interruption. World collision and native movement timing are not simulated accurately by mocks.

`PhotoOutput` is a pure, closed-group planner for AA/JPEG. Its strict tuple validator is deliberately separate from the general numeric CVar planner. Arbitrary keys, malformed tuples, unsupported values and unsafe observations cannot enter this path. `WriteBoundary.NewPhotoOutput` performs all actual output writes through the **same sole `nativeSet` call site** as other controllers; captures originals first; serializes with other writers; checks all dependent values; performs immediate and scheduled verification; and bounds compensation to observed matching changes. A dependent/foreign change is preserved with recovery rather than overwritten. Renderer support is rechecked before subsequent AA writes. Failed restoration retains the record.

Ray shadows use a narrow native-option descriptor and the existing photo-bank planner/recovery path. They do not create a second original for the same key. `Camera.Exit` coordinates output, zoom, photo lighting, names, framing and photo-quality return; the HUD is shown first. Exiting during a pending output operation finishes verification before the return sequence. Startup/reload still does not write or replay native changes.

`PhotoComposition` stores guides/framing/zoom independently of `PhotoConfig` looks. Schema **15** migrates schema 14 without losing preferences, completed setup, saved looks or journals. Photo-look format 2 adds neutral edge-light defaults; earlier LSPHOTO1 transfers still import. The export includes numeric/allowlisted camera/output recovery and capability fields, but no saved composition names, chat, character names or foreign addon data. SavedVariables are not immediately durable storage; crash-proof restoration is not claimed.

## Installation and owner test

1. Exit Camera Mode normally, then close WoW. Extract the supplied beta.13 ZIP. Replace the installed **LumenShift folder** with the complete folder from the ZIP; retain SavedVariables. The final TOC is `_forever_/Interface/AddOns/LumenShift/LumenShift.toc`, with Core, UI, Media and Bindings.xml alongside it. Do not install the ZIP itself or just the TOC. No reset or repeated setup is needed.
2. Disable Narcissus and its modules at character selection for the first run. Enable LumenShift. Enter Camera from the LumenShift launcher/wheel; all six Photo Studio tabs must appear. No slash command is necessary.
3. Recheck Phase 1: choose a pose, try a two-second one-shot capture, then a three-shot burst and Cancel. Drag warmth, switch tabs, and Undo the look. Use H and an external screenshot; Escape must exit.
4. In Frame, scroll to World camera. Try Closer, Farther and Return zoom. Hold orbit briefly in each direction; release and move the pointer off the button to verify it stops. Try H and Escape during a hold. Collision can limit zoom; compare the displayed actual distance. A normal manual camera adjustment must be preserved rather than repeatedly overwritten.
5. Try Shoulder offset and Dynamic framing/footroom where available. Restore FOV separately, then Restore all framing. A native comfort restriction should explain only that unavailable adjustment; other tools must remain usable. Native camera warnings, motion feel and accessibility behavior are still owner observations.
6. Under Capture, scroll past the timer controls. Apply one modest AA choice, inspect edges and frame rate, then Restore antialiasing. Test supported ray shadows separately. JPEG quality is relevant only for JPEG output: Apply, capture an image, then Restore. Confirm the normal graphics preferences return after Exit. Unsupported renderer options should be unavailable locally, without blocking capture.
7. Try Sun Flare or Blue Hour and the Edge light sliders on Look. Save a look. Separately save a composition, move framing/zoom, then Apply that composition. Confirm it restores the chosen composition without loading the saved look or changing AA/lighting.
8. Exit with Escape. Verify HUD, names, lighting, framing and applied quality/output settings return where still owned. Re-enter: no ongoing orbit, stale capture or unrequested output change should occur. If a native operation fails or a panel behaves differently, export the complete report from Studio; keep originals and saved settings rather than resetting them.

Remaining native acceptance includes actual movement/collision, camera-event ordering, fonts/input/taint, AA/ray performance and visual changes, JPEG files, and optional Narcissus coexistence. Portrait Stage/3D actors, public release and CurseForge publication are not part of this delivery. Work remains on `feat/beta-integration`, draft PR #5; no merge is performed.
