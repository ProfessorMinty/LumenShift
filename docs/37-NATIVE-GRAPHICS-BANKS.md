# Dev.12 — native normal and raid graphics

Observed/reviewed 2026-11-07. The owner requested native graphics selection while preserving their current custom settings, an understandable recommendation path, and independent raid/battleground settings. Implementation stays on `feat/beta-integration`, PR #5. This is an experimental development feature with working controls, not a claimed complete renderer or hardware benchmark.

## What is implemented

Setup has **Appearance** and **Graphics** pages. Appearance retains Original / Game Defaults for Brightness and Contrast. Graphics offers **Keep current**, **WoW recommendation**, and **Choose a level** (1–10), plus an independent raid/battleground bank and its enable checkbox. Existing setup completion is preserved. Reopening setup retains saved choices; choosing controls or **Save & Close** never applies them. **Apply & Reload UI** saves, applies the selected banks, waits for fresh verification, then reloads. Failure keeps preferences and originals without reloading. With both banks kept, **Finish & Reload UI** remains a plain save/reload.

Studio → **Graphics Quality** exposes the same controls without requiring setup or reload. **Review changes** is a read-only scrollable preview. **Apply graphics** changes selected banks. Scroll down to **Restore everyday graphics** / **Restore raid graphics** when originals exist. Restore explicitly replaces that bank's current values with captured originals, including after an external change. It does not require a confirmation card. Current state and recovery detail appear on the page and in the diagnostic report.

Balanced/Vista/Performance remain under **Detail profiles**. Their sharpening and other bounded refinements are separate from the new native levels and from visual modes. Simultaneous ownership of overlapping everyday/detail keys is refused with a specific restore instruction, rather than silently recapturing or destroying either original. Nonoverlapping settings remain independent.

## Evidence and API decisions

Sources and client evidence are cataloged in [35](35-GRAPHICS-SELECTION-AND-RECOMMENDATIONS.md). The reference is the mirrored Blizzard Forever UI at **70862**, commit [`9dc84f0d3bbae1768ac3405b3716000bd93eda06`](https://github.com/Gethe/wow-ui-source/tree/9dc84f0d3bbae1768ac3405b3716000bd93eda06). This is source confirmation, not certification of new live operations.

- [Graphics.lua](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_SettingsDefinitions_Shared/Graphics.lua#L1197) maps each component using `GetGraphicsCVarValueForQualityLevel(key, displayedLevel - 1, raid)`. Setting only the overall CVar is insufficient. Values must be accessible finite integers in the named source domain.
- [GraphicsOverrides.lua](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_Settings_Shared/Mainline/GraphicsOverrides.lua#L1) supplies exact normal/raid keys and conditional features. No arbitrary RAID-prefixed key is invented. One canonical spelling owns each setting.
- Dropdown support uses native `IsGraphicsSettingValueSupported(...) == 0`. False, true, errors and other numbers are not success. Overall/view/environment/clutter sliders use their source bounds; the source does not call the dropdown support function for these sliders. Optional PBR, lighting, outlines and spell density use their boolean capability APIs.
- Recommendations use each current `GetCVarDefault` result, independently. No average or rounded overall level replaces a custom recommendation vector. The UI describes this as the game's defaults, not an FPS measurement. Missing APIs produce a specific refusal for that operation; ordinary modes and Keep Current stay usable.
- Normal particles honor the native minimum of 1. LumenShift also keeps projected textures on and avoids the disabled particle choice on clients without secondary lighting. These are explicit combat-cue refinements to the returned recipe/defaults, visible in preview; the result may therefore differ from an unmodified native low preset. This does not guarantee every combat effect at every spell-density setting.
- Current-level text compares the component vector with the **unmodified native recipe**. Mismatches show Custom. It cannot identify every hidden leaf override solely from matching proxy values.
- Native child settings commit before the overall selector, consistent with [SettingsPanel.lua](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_Settings_Shared/Blizzard_SettingsPanel.lua#L28). The addon does not invoke the broad native Settings Apply/Defaults machinery, active-bank selector, GPU Auto Detect, console interpreter or a guessed benchmark API.
- Known leaf names come from the older **70532** [native CVar capture](https://github.com/Ketho/BlizzardInterfaceResources/blob/d1ee569878094270c0ad8d8b00de0762158fd578/Resources/CVars.lua). Their source presence does not prove availability, range or complete dependencies on the current client. They are read for capture; the new bank engine can only directly write a leaf's exact captured original during restoration/compensation.

## Architecture and failure behavior

`Core/NativeGraphics.lua` owns the allowlist, choice validation, recipes, observations, equality-only restoration descriptors and ordering. `UI/Graphics.lua` shares controls/preview/status between Setup and Studio. `WriteBoundary.NewNativeGraphics` owns the native transaction. Every write, including compensation and leaf restoration, passes the common Planner/Recovery model and the existing single private native setter. No additional writer or native Settings proxy bypass exists.

Schema **7** adds validated `graphics.choices`, independent `graphics.records.normal` / `.raid`, and numeric allowlisted `graphics.sideEffects`. Migrations from 1–6 preserve the existing preferences, selected visual snapshot, completion and journals. Original and expected maps have identical known keys belonging to one bank. Unknown keys, invalid numbers, invalid choice enums and malformed records quarantine the saved data without deleting it. Defaults have both banks on Keep Current and retain the existing raid checkbox.

Before the first setter, the engine captures every available, numerically valid, unrestricted known parent/leaf value for that bank as its original map. It records a pending operation before writing. Later applies never overwrite this first original. Both requested recipes and mandatory direct targets are preflighted before either bank starts. The banks commit sequentially: a later raid failure can leave a successfully applied normal bank; it is not represented as an atomic transaction.

Each step verifies identity, combat, APIs, flags and the complete expected captured map, builds a one-key plan, checks the native setter's boolean result and effective readback, then observes known induced values. A later timer performs a separate fresh read of targets and the expected map. Parent-induced known leaf changes are captured in the expected map while originals remain untouched. An unexpected other-bank or watched visual change stops further steps and is retained in the report; it is not silently overwritten.

A failed new Apply can attempt **one bounded compensation pass** while its expected captured state still matches. It restores the pre-operation selector, component selectors and then captured leaf overrides, with the raid flag last. No automatic compensation is attempted after an external conflict or during explicit recovery. Failed compensation/restoration retains recovery information; there is no retry loop. Successful explicit restoration requires exact raw equality for all captured originals, including a custom `-1` selector or a string such as `05432.00`.

Startup and reload never apply or restore graphics. A completed matching record may participate in a later explicit Apply. Pending/failed/conflicting or different-signature records require an explicit Restore. Version differences themselves remain warnings; current per-operation evidence decides whether an action is possible. Native callback reentry is blocked across the new engine and the existing brightness, experiment, name and tier operations, including preflight and delayed verification.

SavedVariables is not immediately durable. The record is available in memory/export before writes but may be lost on a process crash before the game saves it. This implementation does not claim crash-proof recovery.

## Deliberate limits

Captures cover an explicit list of **available known values**, not all renderer state. Unavailable leaves are listed as uncaptured in export and never fabricated. Unknown dependencies, delayed changes beyond the follow-up read, renderer/hardware differences and native canonicalization of raw values remain live-test risks. The engine cannot prove whether a same-bank change occurring inside a native call was a native dependency or another addon. A parent's undocumented effect may fall outside the watch set. Exact whole-game restoration is therefore not claimed.

No automatic zone writer competes with the game's raid-bank selection. Actual activation in raids/battlegrounds and other content needs observation. Resolution, renderer/GPU, HDR, AA, render scale, FPS caps and shared settings are outside this flow. No maximum-quality guarantee or measured performance benefit is asserted. The wider image-quality/mode roadmap in [33](33-FOREVER-GRAPHICS-DEEP-DIVE.md) is still incomplete.

## Validation and owner acceptance

The complete Lua 5.1 suite covers all prior tests plus native-bank startup/preview nonmutation, recipe/default endpoints, conditional hardware, invalid/secret results, separate banks/visual modes, capture-before-write, induced custom-leaf restoration, exact originals, preflight of both banks, clamping, failure/compensation, external conflicts, reload, callback reentry, schema migrations, saved setup choices, failed Apply without reload, bounded UI reuse and partial bank completion. **268 Lua 5.1 mocks passed, 0 failed**, including 30 new native-bank cases. **9 Python packaging tests passed.** Structural and syntax checks passed for 35 runtime modules, 10 Lua test files and 4 binding bodies. The off-client layout model was visually reviewed for both setup pages, Studio and the preview. These are simulated native APIs and off-client layouts, not game results. Archive-specific results are in the build receipt.

Use [the installation and testing guide](21-BETA-USER-GUIDE.md). First retain existing graphics and confirm the two-page setup saves/reloads. For a controlled graphics check, select only Everyday at one step from the current level, review/apply, wait for completion, then Restore everyday graphics and compare the report's originals/current values. Repeat separately for raid and its checkbox, then verify a two-bank operation. Compare visible scene changes and normal/raid behavior independently. Restore before uninstalling/downgrading; keep the full report if a restore fails.

Owner-operated native dev.12 tests, FPS effects, complete dependency closure, native font/input/scrolling and cross-addon window coexistence remain **NOT TESTED**. Prior dev.6 native Brightness success and dev.10 read-only quality observations remain valid but do not certify this feature. No installed game was changed, no PR was merged, and nothing was published.
