# Forever graphics investigation and mode direction

Research date: **2026-11-07**. Target evidence: Forever **1.60.1 / 70862 / 16001** UI source, an older **70532** native console capture, and the owner's already accepted Brightness evidence. This document separates implementation from proposed development. No game settings or installed files were changed during this investigation.

## Findings that change the product

The owner's criticism is fair: the six current visual modes mostly differ through Brightness, optional Contrast and UI presentation. The existing bounded quality recipes do not yet amount to a comprehensive high-quality renderer configuration. More substantial native improvements are possible, but their controls differ in type, hardware support and interactions. Turning every discovered numeric setting upward is not a valid quality strategy.

1. **Real image clarity:** native-resolution rendering, suitable anti-aliasing, anisotropic filtering and the game's sharpening pipeline are the first priority. Sharpening is not new texture detail; excessive strength needs visual testing for halos and shimmer. The Forever sharpness slider is reversed. Dev.10 fixes a built-in recipe that forced `1`, potentially softening an existing `0.2` value; recipes now preserve the captured strength.
2. **Real scene quality:** secondary lighting, shadow tiers, ambient occlusion, compute/depth effects, PBR water and detail distances are stronger tools than a tint overlay. They require supported native choices and dependency-aware restoration. Persistent tier profiles are still unfinished; existing temporary trials are not proof of every affected child setting.
3. **Hidden controls exist**, especially resampling overrides, fog, shadow internals, reflection resolution, particles and ASSAO tuning. Some are renderer implementation details rather than useful user options. Others found in popular addon/guide lists are absent from the older Forever capture.
4. **Original and Game Defaults are different products.** Original is a saved player-selected return look. Game Defaults queries native per-key defaults. Neither should silently reset all video settings, choose a renderer or activate Forever's wider Classic/Enhanced experience preset.

## Image formation: useful quality controls

| Control | Confirmed mapping/evidence | Proposed use and limits |
| --- | --- | --- |
| `Brightness`, `Contrast` | F1 lines 1564–1577: 0–100 UI domains. F3 captured defaults are both `50.000000`; owner values are 45/60. | Read actual originals/defaults at runtime. Contrast is not a substitute for lighting or detail; avoid crushed shadows/highlights. Dev.10 baseline applies these two visual settings only. |
| `Gamma` | F1 lines 1580–1585: 0.3–2.8 UI slider; F3 captured default 1. | Display calibration first; do not use global gamma as a routine mood slider. Not controlled by this build. |
| `ResampleAlwaysSharpen` | F3 line 1330: boolean override allowing sharpening without the FSR upscale pass. | Useful for crispness at native resolution when the renderer honors it. Already an experimental control. Native current-client visual benefit remains to be measured. |
| `ResampleSharpness` | F1 lines 1538–1561 reverses a 0–2 slider. F3 line 1332: captured 0.2, lower values sharpen more; help also mentions -1 disabling. | Expose a user-facing strength control with correct mapping and an off option; existing raw control explains the direction. Do not admit -1 merely because older help mentions it. Dev.10 retains the documented 0–2 domain. |
| `textureFilteringMode` | F1 lines 1273–1289: 0 bilinear, 1 trilinear, 2/3/4/5 = 2x/4x/8x/16x anisotropic. F3 captured 5. | **16x is the quality-oriented candidate**, especially for oblique ground textures. Value 16 would be wrong. Already-at-16x needs no change. Proposed new reversible control, not shipped here. |
| `RenderScale` | F1 lines 875–901 queries native minimum/maximum; F3 captured 1. | Start at 100% native. Supersampling is optional with GPU headroom, not a universal preset. At 150% in both dimensions there are 2.25x as many pixels; 200% has 4x. Actual frame cost is not this simple ratio. |
| `ResampleQuality` | F1 lines 1310–1322: 0 point, 1 bilinear, 2 bicubic, 3 FSR. F3 captured 3. | Coupled to render scale and sharpening. Do not market this as FSR 3, temporal reconstruction or frame generation: the inspected source does not establish those features. |
| `ffxAntiAliasingMode`, `MSAAQuality`, `MSAAAlphaTest` | F1 lines 996–1190: image AA 0 none, 1/2 FXAA, 3 CMAA, 4 CMAA2; choices depend on native capabilities. MSAA options come from the API, and the value may have comma-separated components. | Test supported CMAA2/MSAA combinations for clarity and foliage edges. No universal “MSAA 8” assignment. Needs a structured value descriptor and atomic multi-key planning, not the numeric research probe. |
| `vrsValar` | F1 native VRS choices: 0 disabled, 1 standard, 2 aggressive. | More aggressive shading reduction is not “higher quality.” Leave performance-oriented VRS tuning explicit and hardware-dependent. |
| Texture resolution / high-resolution assets | F1/F2 `graphicsTextureResolution` and availability of high-resolution texture support/install state. | Prefer the highest supported native texture choice with adequate VRAM. An addon cannot manufacture or download missing texture assets. Preserve native support checks rather than assume enum direction. |
| HDR/display/renderer | F1 has HDR controls and renderer/adapter choices; some require graphics or client restart. | Monitor calibration, renderer, adapter, resolution mode and thread/debug flags stay in the game's settings. Not per-mode switching. |

## Scene rendering, including console-only candidates

“Hidden” below means an implementation-level setting with no direct control found in the inspected graphics page; tiers may still modify it. The current settings page is not the entire engine. F3 help is captured metadata, not guaranteed enforcement.

| Family | Evidence and candidates | Product decision |
| --- | --- | --- |
| Shadows | F1 `graphicsShadowQuality` 0–5. F3 `shadowMode`, `shadowTextureSize`, `shadowSoft`, `shadowRt`. Captured shadow texture help describes 1024–2048. | Prioritize supported native shadow tiers. Do not invent 8192 as a safe texture maximum. Leaf/tier interactions need mapping. |
| Secondary lighting | F1 `graphicsLightMode` 0–3, gated by `IsSecondaryLightingSupported()`. | Major candidate for richer scenes. Existing lights/materials only; not a player-attached torch API. |
| Ray-traced shadows | F1 offers `shadowrt` only on the path where secondary lighting is unsupported, and not on Mac. | Do not prescribe ray tracing plus maximum secondary lighting as a universal Forever recipe. Use actual capability paths. |
| Ambient occlusion | F1 `graphicsSSAO` 0–4; F3 `SSAO` and `assao*` internals. | Native high/ultra tiers are first choice. A convincing improvement should add contact depth without muddying the entire scene. |
| Hidden ASSAO tuning | F3 `assaoRadius`, `assaoShadowMult`, `assaoDetailShadowStrength`, `assaoBlurPassCount`, `assaoSharpness`. Detail strength help warns of temporal instability/aliasing. Some help/default values are inconsistent, e.g. horizon threshold. | Research observations only. Huge radius ranges in help are not sensible recommendations. Do not maximize all parameters; native tiers and moving-scene testing come first. |
| Depth and compute effects | F1 `graphicsDepthEffects` 0–3, `graphicsComputeEffects` 0–4. F3 `DepthBasedOpacity` is a separate leaf. | Investigate supported high-quality paths and soft-edge effects. Tier domains do not prove effect-specific dependencies. |
| Water and reflections | F1 `graphicsLiquidDetail` 0–3; PBR `graphicsPBRLiquidDetail` 0–2 with `IsPBRWaterSupported()`. F3 `reflectionMode`, `reflectionDownscale`, `rippleDetail`, `waterDetail`, `pbrLiquidDetail`. | Prefer supported PBR/native water choices. Reflection enums/downscale direction are not established by an arbitrary author's “ultra” list. Capture coastline/water comparisons and watch dependent keys. |
| Fog/atmosphere | F3 `volumeFog`, `volumeFogInterior`, `volumeFogLevel` (help 0–3), `sunShafts`, `horizonStart`. | Visibility and atmosphere trade off. Removing fog everywhere is not higher fidelity. Preserve authored atmosphere by default; investigate explicit accessibility variants. No automatic fog disable in Night Vision. |
| Bloom | F1 `bloomUserMult` 0–1 in 0.2 steps, conditional on `IsLinearEnabledOnStart()`. F3 also has `bloomEnable`. | Useful optional Clarity/Cinematic variation on supported pipelines. Existing leaf control does not establish every pipeline's visual response. Avoid forcing hidden enable flags without support/dependency evidence. |
| Terrain/object detail | F3 `farclip`, `terrainLodDist`, `lodObjectCullSize`, `lodObjectFadeScale`, `horizonStart`. | Reducing cull size may retain smaller objects; higher fade/distance may retain detail longer. Treat these as hypotheses to measure. Replace percentage-only recipes with supported quality targets and distance budgets after native validation. Farclip 5000/7000 is not established as a universal maximum. |
| Grass/foliage | F3 `groundEffectDensity`, `groundEffectDist`, `groundEffectFade`. | Density and draw/fade distances need coordinated changes; single-setting maxima can create pop-in or poor performance. Owner's density 256 is a preference, not a captured Blizzard default. |
| Particles/spells | F1 particle tiers have different enums depending on secondary-lighting support; projected-texture disabling carries a combat-cue warning. F3 `particleDensity`, `particleMTDensity`. | Preserve essential combat cues. Performance mode must not silently remove projected effects. Test in motion and busy encounters, not just an empty landscape. |
| Weather and clouds | F3 canonical `weatherDensity`, `SkyCloudLOD`; cloud default 0 does not establish that a larger number is better. | Weather intensity is aesthetic as well as quality. Test real weather; do not blindly maximize a LOD selector. |
| Raid/battleground overrides | F2/F3 separate raid graphics settings and `RAID*` distance/detail controls. | A profile needs explicit normal/raid scope. Avoid surprise changes when entering a raid; current dev.10 does not implement a separate raid profile system. |

F3 does **not** contain these exact names found in circulated tweak lists or comparator code: `horizonfarclip`, `horizonFarclipScale`, `detailDoodleDensity`, `detailDoodadAlpha`, `shadowLevel`, `shadowCascadeAmount`, `shadowCascadeNum`, `SSFX`, `SSGI`, `volumeFogDensity`, `fogDensity`, `rays`, `raysUltra`, `gxMultisample`, `SSAOType`, `SSAODistance`, `lightMode`, `gxMaxFrameLatency`. This is **absence in the 70532 capture**, not proof of removal/absence in every later build. None should become an automatic target without fresh evidence. `MSAACoverage` is not a substitute for correctly parsing `MSAAQuality` either.

## Make each mode useful, without disguising an overlay as a shader

The following is the **proposed next implementation direction**, not a claim that dev.10 already applies it. Image quality belongs to an independent profile; mode-specific optical overrides must be explicit and combined through one effective-target planner. Switching mode must never silently replace the user's quality profile.

| Mode | Current dev.10 | Meaningful development direction |
| --- | --- | --- |
| **Original / Game Defaults** | Chosen Brightness/Contrast snapshot; no tint/vignette. Exact pre-change recovery remains separate. | Preserve the selected visual home look. Add an independently chosen quality snapshot/default option later, with a complete supported-key list. No whole-game reset implied. |
| **Night Vision** | Brightness 75, optional Contrast, optional green tint/vignette/audio. | Visibility-first optical settings: readable dark detail, controlled contrast, optional sharpening and reduced supported bloom. Preserve fog and combat cues by default. Test caves and night scenes for highlight clipping. No true monochrome phosphor or automatic darkness detector promised. |
| **Cinematic** | Authored Brightness 42, optional Contrast and amber presentation. | Pair with an explicitly selected cinematic quality recipe: supported lighting, shadows, AO, water and good AA. Optional restrained bloom and composition effects. This is the largest plausible scene-fidelity improvement; it costs real GPU/CPU time. |
| **Lantern** | Brightness 65 and optional warm UI tint. | Tune warmth/presentation around the world's existing local/secondary lighting, with enough contrast to keep shaded areas atmospheric. No inspected addon API creates a dynamic handheld world light; the name must not imply that capability. |
| **Clarity** | Brightness 70, no default tint/vignette; optional Contrast. | Native-resolution/AA choices, anisotropic filtering, optional sharpening, restrained bloom and legible contrast. Target texture/edge readability in motion, not just higher brightness or oversharpened stills. |
| **Moonlight** | Brightness 55 and optional cool UI tint/vignette. | Preserve night atmosphere and fog while recovering useful dark detail. Supported lighting/shadows and soft bloom may help, but an addon cannot freely change world time, recolor the actual moonlight or inject a color-grading shader through the inspected APIs. |
| **Camera** | Native HUD visibility plus optional friendly player/pet names. Independent of visuals/quality. | Keep it an independent capture workflow; optional composition aids later. Do not make screenshot-quality rendering mandatory for normal gameplay. |

Current numeric visual defaults above are **LumenShift-authored**, not Blizzard recommendations. Their distinct native visual quality is not yet accepted by live comparison tests. Optional overlays only draw on the UI; they do not relight geometry, alter material shaders, inject LUTs or create depth-aware optical effects.

## Recommended implementation sequence and acceptance

1. **Image-quality controls:** add native capability-backed anisotropic filtering, resampling and AA descriptors, including structured MSAA values; preserve precise originals. Expose actual controls, current/default values, meaningful strength labels and an optional advanced view. Acceptance: missing/restricted APIs remain usable elsewhere; supported values and effective readback match; explicit restore returns every captured raw value; AA multi-key changes are atomic or visibly recoverable.
2. **Persistent lighting/detail quality:** map tier changes against the expanded observed catalog, including normal/raid variants and actual child changes. Then build hardware-aware Balanced/Vista/Performance recipes with supported native tiers, texture filtering and coordinated distance/foliage choices. Acceptance: full changed-key restoration, external-edit preservation, unsupported-option omission and a readable applied/omitted list. Percentage deltas are not the finished product; unknown side effects are not silently certified by matching the tier alone.
3. **Mode optics:** introduce per-mode optical deltas and optional companion-quality selection with explicit precedence, never two owners for one CVar. Acceptance: repeated mode switching leaves the quality choice intact, switching back restores that effective quality, conflict/error/reload behavior preserves original records, and every mode passes a recognizable visual A/B comparison.
4. **Performance-aware refinement:** user-started stationary and repeatable route comparisons, same weather/time/camera where possible, stable warm-up and identical observation windows. Report FPS/frame-time observations and scene conditions, not a universal percentage benefit. Include motion, foliage shimmer, water, interiors, spells and a representative busy encounter. Do not change graphics automatically based on a brief FPS dip.

There is no single “best everything” recipe for every display, GPU, CPU and gameplay context. The quality-oriented starting hypothesis is native resolution, high-quality textures, 16x anisotropic filtering, supported good AA, appropriately restrained sharpening, then the highest lighting/shadow/water/AO/detail combination that meets the user's performance target. Supersampling and very long distances are optional costly extras. No measured optimum or FPS result is claimed here.
